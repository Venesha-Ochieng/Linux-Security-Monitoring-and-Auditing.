# Laboratory Overview

This laboratory provided practical experience in Linux security monitoring, auditing, and control assurance activities. The exercises involved configuring and validating the Linux auditing subsystem, reviewing authentication and system logs, performing security assessments of a Linux host, and analysing the resulting evidence from a governance and security assurance perspective.

The laboratory demonstrated how technical monitoring and auditing activities support organisational security governance by providing objective evidence about the effectiveness of implemented controls. Rather than focusing solely on command execution, the activities required interpretation of collected evidence to determine whether security controls were functioning as intended.

Issues identified during the exercises were evaluated according to their security impact, governance significance, control ownership, remediation requirements, and the need for follow-up monitoring or retesting. # Module 1: System Auditing with auditd

The Linux Auditing System provides a mechanism for collecting detailed records of security-relevant activities occurring on a system. The **auditd** service acts as the userspace component responsible for receiving, storing, and managing audit events generated by the Linux kernel.

Audit records can be used to support forensic investigations, compliance requirements, security monitoring, incident response activities, and governance assurance processes. By maintaining a reliable audit trail, organisations can demonstrate accountability, monitor privileged activities, and detect suspicious or unauthorised actions affecting critical systems and data.

## Activity 1.2: Configure Audit Rules

### 1.2.1 Create a Dedicated Audit Rules File

To maintain good configuration management practices, a separate custom audit rules file was created instead of modifying the primary audit configuration directly. This approach simplifies administration, reduces the risk of accidental changes to default settings, and makes future maintenance easier.

The following command was used to create and edit a custom rules file:

```bash
sudo nano /etc/audit/rules.d/custom.rules
```

### 1.2.2 Add Rules to Monitor Sensitive Account Files

To monitor changes to critical account and authentication files, audit rules were added to the custom audit configuration file. These files contain user account information and password-related data that are essential to system security.

The following audit rules were configured:

```bash
-w /etc/passwd -p rwxa -k passwd_changes
-w /etc/shadow -p rwxa -k shadow_changes
```

### Purpose of the Rules

- `-w` specifies the file or directory to watch.
- `-p rwxa` monitors all relevant operations:
  - `r` = read
  - `w` = write
  - `x` = execute
  - `a` = attribute changes
